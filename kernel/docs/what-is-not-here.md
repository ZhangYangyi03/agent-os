# 这套东西不做什么

写清楚，免得以后有人（包括我自己）以为它有别的用途。

## 不做的

- 不用任何"绕过驱动签名"的手段。不碰 KDU 之类的漏洞利用链，也不碰
  "拿微软签过名的老驱动把未签名代码塞进内核"的路子。那类东西是恶意软件的
  常规入口，正经开发用不着，正规门就在 enable-testsigning.ps1 里。
- 不改微码，也不可能改。CPU 只认厂商私钥，这一层没有任何个人能碰。
- 不碰别人的机器。这套东西的每一条命令都作用在你自己有权管理的那台机器上。
- 不替人破除付费软件的授权保护。

## 为什么这条线要划

不是能力不够划的，是这套东西的用途决定的：同样一个能加载进内核的驱动，
用来观察自己写的东西，是学习；用来藏在别人机器里不被发现，是 rootkit。
技术一模一样，区别只在有没有得到那台机器主人的同意。

kernel-lab 里的驱动只有一个 IOCTL，返回的是当前调用者的 PID 和系统时间。
它不隐藏自己（未签名加载在测试模式下是显眼的），不劫持任何系统调用，
不改任何其他进程的内存。这样即使它跑在别人的机器上，也藏不住 ——
这是故意的。

## 法律

自己机器上为了学习、兼容性研究去分析内核和驱动，通常没问题。
分发出来的东西如果绕过了别人的授权保护，那是侵权，情节严重的算刑事。
这条线跟技术难度无关。
